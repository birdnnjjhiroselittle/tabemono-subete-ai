# 統合最適化：食べる人の生活・健康と、食べものの生産・流通を一つにつなぐ

**目的と情報は一つにまとめ、決めることは分散させる。**

> この資料は、たべものすべてAIが「食べる人の生活と健康」と「食べものの生産・流通」を統括的に最適化する考え方を、式と図で説明するものです。
> モデルは考え方を示すための簡単なものです。

## 1. 2つの「一元化」

| | 中央で一元管理（とらない） | 論理的に一元・実際は分散（目指す） |
|---|---|---|
| データ | 全員の食事・健康・在庫を1つのサーバーに集める | データは各家庭・各お店の端末に置き、共通の形式でつなぐ |
| 決める人 | 中央のAIが「誰が何を食べ、農家が何を作るか」を決める | 家庭・お店・農家のAIが、それぞれ自分にとっての最適を決める |
| 調整 | 命令する | **共通の信号**（需要の合計・足りない栄養・影の価格）で自然にそろう |
| 弱点 | 知識が集まりきらない（ハイエク）、1か所止まると全部止まる、権力の集中、監視社会 | 信号の設計を間違えると、ずれが出る |

一元化するのは、次の3つだけです。

1. **目的の式**：何を良しとするか（健康・満足・ロス・費用・環境）
2. **データの形式**：食材・在庫・需要・栄養を、みんなが同じ言葉で表す
3. **信号**：需要と供給のずれを知らせる、誰の分か分からない数字

## 2. 社会全体の最適化を一つの式で書く

### 登場するもの

| 記号 | 意味 |
|---|---|
| $i$ | 食べる人（家庭） |
| $s$ | お店・飲食店 |
| $f$ | 農家・漁業・メーカー（作る側） |
| $k$ | 食材の種類 |
| $r,\ t$ | 地域と日 |
| $x_{i}$ | 人 $i$ が食べるもの（献立） |
| $q_{f}$ | 作る側 $f$ が作る・出荷する量 |
| $w$ | 捨てられる量（食品ロス） |

### 目的

$$
\max \quad
\sum_i \Bigl( \underbrace{H_i(x_i)}_{\text{健康}} + \underbrace{U_i(x_i)}_{\text{おいしさ・満足}} \Bigr)
\;-\; \underbrace{\lambda_w \, W}_{\text{食品ロス}}
\;-\; \underbrace{C(q)}_{\text{生産・流通の費用}}
\;-\; \underbrace{\lambda_e \, E}_{\text{CO2}}
$$

### 条件

$$
\underbrace{\sum_f q_{f,k,r,t}}_{\text{作って届く量}} + \underbrace{I_{k,r,t-1}}_{\text{前日の在庫}}
\;=\;
\underbrace{\sum_i x_{i,k,r,t}}_{\text{食べる量}} + \underbrace{w_{k,r,t}}_{\text{捨てる量}} + \underbrace{I_{k,r,t}}_{\text{残る在庫}}
\qquad (\text{すべての } k, r, t)
$$

- **安全**：アレルギーの食材は $x_{i,k} = 0$、食中毒の危険がある物は出さない（**絶対の条件**）
- **健康**：栄養は日本人の食事摂取基準などの範囲内、持病の制限は上限として守る
- **パレート改善**：参加したどの人・お店・農家も、参加前より悪くならない

$$
V_j(\text{参加後}) \;\ge\; V_j(\text{参加前}) \qquad (\text{すべての関係者 } j)
$$

### 優先順位

健康と食品ロスがぶつかったときの順番は、これまでと同じです。

```
① 安全 > ② 健康 > ③ 好み > ④ 食品ロス > ⑤ 食費
```

①と②は「重み」ではなく **条件** として入れます。重みにすると、ロスを減らすために健康を少し悪くする答えが出てしまうからです。

## 3. 双対分解：分けて解いても全体の最適になる

この式を中央のコンピューターで一度に解こうとすると、全員の健康データ・冷蔵庫・作付け計画を集めることになります。それは、プライバシーの面でも現実の面でもできません。

そこで、**需給を合わせる条件**（第2節の等式）に、ラグランジュ乗数 $p_{k,r,t}$ を付けます。これが **影の価格** です。

$$
L = \sum_i \bigl(H_i + U_i\bigr) - \lambda_w W - C(q) - \lambda_e E
+ \sum_{k,r,t} p_{k,r,t}\Bigl(\sum_f q_{f,k,r,t} + I_{k,r,t-1} - \sum_i x_{i,k,r,t} - w_{k,r,t} - I_{k,r,t}\Bigr)
$$

$p$ を固定すると、この式は **関係者ごとの小さな問題に分かれます**。

| 関係者 | それぞれが解く問題 | 必要な情報 |
|---|---|---|
| 家庭 $i$ | $\max_{x_i}\ H_i(x_i) + U_i(x_i) - \sum_k p_k x_{i,k}$ | 自分の在庫・健康・好み（**外に出さない**）と、配られた $p$ |
| 作る側 $f$ | $\max_{q_f}\ \sum_k p_k q_{f,k} - C_f(q_f)$ | 自分の費用と、配られた $p$ |
| お店・物流 | 在庫と運ぶ量を、$p$ の地域差・日の差で決める | 自分の在庫と、配られた $p$ |

そして $p$ は、ずれに合わせて少しずつ直します。

$$
p_{k,r,t} \;\leftarrow\; p_{k,r,t} + \alpha \Bigl(\underbrace{\sum_i x_{i,k,r,t}}_{\text{食べる予定の合計}} - \underbrace{\sum_f q_{f,k,r,t} - I_{k,r,t-1}}_{\text{届く量と在庫}}\Bigr)
$$

- 足りない食材は $p$ が上がる → 家庭は別の料理を選び、作る側は増やす
- 余る食材は $p$ が下がる → 家庭はその食材の料理を選び、作る側は減らす
- くり返すと、**中央で一度に解いた答えと同じ所へ近づく**（目的が凹関数などの条件のもとで）

### ここで共有されるのは2つの数字だけ

- 配る：影の価格 $p$（町全体で、どの食材がどれだけ足りない・余るか）
- 集める：$\sum_i x_i$（食べる予定の **合計** だけ。誰が何を食べるかは分からない）

これは、[経済学](economics.md) 第5章の「値段 ＋ 誰の分か分からない合計数」という信号と同じものです。ハイエクの「値段は散らばった知識をまとめる」を、**食べものが傷む速さに合わせて毎日・毎時間** 動かすしくみといえます。

## 4. 影の価格を、日常の言葉で配る

影の価格は、そのまま値札にする必要はありません。各AIが、それぞれの相手に合った言葉に直します。

| 受け取る人 | 影の価格の伝え方 |
|---|---|
| 家庭 | 🎧「鮭は今週、町で予定が多いようです。ほうれん草と卵のキッシュもおいしいですよ」 |
| お店 | 「来週は32℃が続き、冷たい麺の予定が20%増。そうめんの仕入れを増やし、鍋つゆは減らしましょう」 |
| 物流 | 「A町はトマトが余り、B町は足りません。明日の便で回しましょう」 |
| 農家 | 「この地域では、緑の野菜が足りていない人が多い。来季のほうれん草・小松菜の作付けを検討しては」 |
| 地域の基金 | 「お店Cの定価の売上が減っています。基金からの補てんを」 |

値段として実際に動かすのは、お店の値引きなどの一部だけです。それ以外は **お知らせ（ナッジ）** として伝え、従うかどうかは本人が決めます。

## 5. 時間の長さで分ける階層構造

決めることの時間の長さが違うので、層に分けて、層どうしは信号でつなぎます。

```
年        ┌ 町・国・世界：ルール、基金、得の分け方、損をした人の確認
          │
季節〜年   ├ 農家・漁業：作付け、出荷の時期          ← 町の栄養の不足、長期の需要、気候
          │
週〜月     ├ 加工・メーカー：生産計画                ← 需要の見通し、余りそうな原料
          │
日〜週     ├ 物流：運ぶ量・ルート・保管温度          ← 地域ごとの需要予測、気温
          │
日        ├ お店・飲食店：仕入れ・値引き・作る量      ← 家庭の「来週買う予定」の合計
          │
時間〜日   └ 人・家庭：献立、置き場所、買う量         ← 在庫、気温、予定、健康目標
```

- **上の層は、下の層の「範囲」を決める**（例：農家が作った量が、お店が仕入れられる上限になる）
- **下の層は、上の層に「需要」を返す**（例：家庭の予定の合計が、お店の仕入れの根拠になる）
- 家庭の層の詳しいしくみは [家の食べもの見守りとコントロール](home-control.md)

### 人の生活と健康も、同じ式に入っている

| 生活・健康の情報 | 式のどこに入るか |
|---|---|
| アレルギー・持病 | 条件（$x_{i,k}=0$、栄養の上限） |
| 体重・血圧・健診の結果 | 健康の評価 $H_i$ |
| 好み・食べたい気持ち・飽き | 満足 $U_i$ |
| 予定（出張・来客）、体調 | 食べる人数・食数（需要） |
| 気温・季節 | 食べたくなる料理の確率、傷む速さ |

これらはすべて **家庭の端末の中** で使われ、外へ出るのは「食べる予定の合計」だけです。

## 6. 食のデジタルツイン

町全体の食べものの流れを、コンピューターの中に **仮想の分身（デジタルツイン）** として再現します。中身は、個人が分からない合計の数字と、公開されている統計だけです。

```
  農家 ──→ 市場・加工 ──→ 物流 ──→ お店 ──→ 家庭 ──→ 食べる／余る ──→ おすそ分け／子ども食堂／堆肥
   ↑                                                        │
   └──────────── 需要・栄養の不足・余りの見通し ─────────────┘
```

使い道：

- **もしもの練習**：「台風で葉物が3割減ったら？」「猛暑が2週間続いたら？」「物価が上がったら？」を事前に試す
- **政策・ルールの事前確認**：値引きのルールや基金の配り方を変えたとき、損をする関係者が出ないかを先に調べる
- **効果の見える化**：食品ロス量・野菜の摂取量・医療費の見込み・CO2を、町ごとに比べる

## 7. 共通のデータ形式

つなぐために、みんなが同じ言葉で表す **開かれたデータ形式** を決めます（オープンソースで公開）。

| データ | 例 | 誰が持つか | 外に出るか |
|---|---|---|---|
| 食材 | 「トマト（中玉）」の共通コード、栄養、保存の目安、温度による傷む速さ | 公開 | 公開データ |
| 家庭の在庫 | トマト 3個、キッチン常温、あと2日 | 家庭 | **出ない** |
| 健康 | アレルギー、塩分の上限 | 家庭 | **出ない** |
| 需要の合計 | 来週の町のトマトの予定 120kg | 町 | 合計だけ共有 |
| お店の在庫・仕入れ | トマト 80kg、明日入荷 40kg | お店 | お店が選んで共有 |
| 作付け・出荷の見通し | 来月のトマト出荷 2t | 農家 | 農家が選んで共有 |
| 影の価格 | トマト：やや余り | 町（計算） | 公開 |

合計を出すときは、人数が少なすぎて個人が分かってしまわないように、一定の人数未満の地域では出さない、少しだけ雑音を加える（差分プライバシー）などの方法を使います。

## 8. 気をつけること

| 危険 | 内容 | 対策 |
|---|---|---|
| 管理社会 | AIが「最適な食事」を押しつける | 提案だけ。従わなくても不利にならない。オプトイン |
| 数字のごまかし（グッドハートの法則） | 「ロス削減」だけを評価すると、捨てた量を記録しなくなる | 複数の指標で見る（ロス・健康・満足・売上・利益） |
| 弱い立場の人の切り捨て | 全体の効率のために、小さな農家や途上国が損をする | パレート改善を **条件** として入れる。基金で補てん（→ [パレート改善](pareto.md)） |
| 止まったときの混乱 | 信号が止まると、みんなが動けなくなる | 信号がなくても、各家庭・お店は自分だけで動けるようにしておく |
| 独占 | 信号を配る者が力を持つ | 協同組合で運営、町どうしが対等に連合、中央のサーバーを置かない（→ [自律分散](decentralized.md)） |
| モデルの誤り | 予測が外れて、かえって作りすぎ・足りなくなる | 小さく始めて、実際の結果で毎日学び直す。人が最終確認する |
| 健康の誤った助言 | 持病のある人に合わない提案 | 診断しない。医師・栄養士の指示を最優先（→ [健康](health.md)） |

## 9. 段階的な実現

| 段階 | 範囲 | すること |
|---|---|---|
| 1 | 家庭 | 家の中だけで最適化（献立・置き場所・買う量） |
| 2 | 家庭 ＋ 近くのお店 | 「来週買う予定」の合計をお店へ。仕入れ量の提案 |
| 3 | 1つの町 | 家庭・お店・地元の農家をつなぎ、影の価格を毎日配る。デジタルツインで効果を測る |
| 4 | 町と町 | 余りと不足を町どうしで回す。物流を最適化 |
| 5 | 国・世界 | 作付けと輸送の長期の見通しを共有。損をする人がいないかを確認しながら広げる |

**最初から世界全体はやりません。** 1つの町で、家庭・お店・農家の全員が得をすることを確かめてから広げます。
