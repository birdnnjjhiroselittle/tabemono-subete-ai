# 見るだけ・教えるだけ：プライバシーと、個人最適から世界最適へ

## 1. いちばんシンプルな約束

> **たべものすべてAIは、見るだけ。教えるだけ。**
> **画像・映像は、保存しない・送らない・公開しない。**

カメラが見た画像や映像は、その場で「何が・いくつ・期限はいつ」という **文字の情報に変えたら、すぐに消します**。
利用者に返すのは、次のような **ひとことのアドバイスだけ** です。

- 🎧「牛乳は家にまだ1本あります。期限はあさってです」
- 🎧「今日はキャベツと豚肉で回鍋肉がおすすめ。キャベツを使い切れて、野菜もとれます」
- 🎧「塩分を控えているので、漬物より、値引きのほうれん草がいいですね」

**食べものが無駄にならない・おいしい・健康に良い**。この3つを同時に満たす答えを、その人のためだけに教えます。

---

## 2. データの流れ

```
カメラ・マイク
   ↓ （端末の中だけ）
画像・映像 → 「牛乳 1本 期限11/8」のような文字の情報に変える → 画像・映像はすぐ消す
   ↓ （端末の中だけ）
在庫・好み・健康 → AIが考える
   ↓
「今日はこれがおすすめ」 ← 利用者に返すのはこれだけ
```

| 情報 | 保存する場所 | 外に出すか |
|---|---|---|
| 画像・映像 | **保存しない** | 出さない |
| 在庫・期限 | 自分の端末 | 出さない |
| 好み・健康・病歴 | 自分の端末 | 出さない |
| 「来週キャベツを1個買う予定」のような数 | 自分の端末 | **本人が選んだときだけ**、町全体の合計に混ぜて出す（誰の分かは分からない） |

## 3. 「気にしなくなる」の正しい意味

便利で役に立つものは、いずれ誰も気にせず使うようになります。
ただし、それは **「慣れたから」ではなく「気にする必要がない作りだから」** でなければなりません。

| 悪い「気にしなくなる」 | 良い「気にしなくなる」 |
|---|---|
| 本当は集められているのに、慣れて気づかなくなる | そもそも集めていないので、気にする理由がない |
| 規約が長くて読まない | 約束が1行で分かる（「見るだけ・教えるだけ」） |
| 運営する会社を信じるしかない | コードが公開されていて（オープンソース）、誰でも確かめられる |

> **信じてもらうのではなく、確かめられるようにする。** だから、いずれ誰も気にしなくなる。

## 4. 個人最適から世界最適へ

### 4-1. 一人ひとりの最適の積み重ね
一人ひとりが「無駄にならない・おいしい・健康に良い」食べ方をするだけで、
- 家庭のロス（全体の約半分）が減る
- 必要な分だけ買うので、お店の売れ残りも減る
- 健康になるので、医療費も減る

### 4-2. ただし、個人最適を足しただけでは全体最適にならないこともある
| 例 | 何が起きるか |
|---|---|
| みんなに「今日は値引きの鮭がおすすめ」と言う | 鮭が足りなくなり、ほかの食材が余る |
| みんなに「健康には○○がいい」と言う | ○○だけ品切れ・値上がり、取りすぎ |

### 4-3. 解決：薄い信号だけを共有する
中央で全部を決める必要はありません。**町全体の合計数** という薄い信号を共有するだけで、AIどうしが自然に調整できます。

```
一人ひとりのAI：「この人には鮭がおすすめ」
   ↓ 町全体の合計（誰の分かは分からない）：「鮭はもう予定が多い、ほうれん草が余りそう」
一人ひとりのAI：「鮭の代わりに、ほうれん草と卵の料理もおいしいですよ」
   ↓
お店・農家：合計を見て、作る量・仕入れる量を合わせる
```

経済学でいえば、ハイエクが言った **「値段は、みんなの知識を一つにまとめる信号」** と同じ考え方です。
国が全部を計画しなくても、**一人ひとりの最適 ＋ 薄い信号** だけで、町、国、そして世界全体の食べものの最適に近づいていきます（→ [自律分散の運営](decentralized.md)）。

---

## 5. まとめ

1. **見るだけ・教えるだけ**：画像・映像は保存しない・送らない・公開しない
2. **その人のためだけの最適解**：無駄にならない・おいしい・健康に良い
3. **確かめられるから、気にしなくなる**：オープンソースで、誰でも確かめられる
4. **薄い信号で世界へ**：誰の分か分からない合計数だけで、町・国・世界が自然に調整される
