# 企画書：たべものすべてAI

**〜 家の冷蔵庫から、町・国・世界まで。食べものの「ある・ほしい・余る」をすべてつなぐ 〜**

作成日：2026-11-06　｜　提案先：住民・スーパー・商店街・農家、協同組合・NPO、技術パートナー、市町村（参加者の一人として）

---

## 1. 提案の要約

- **たべものすべてAI** は、家庭・お店・町をつないで食品ロスを減らすシステム。
  - 家庭：在庫、期限、食べたい気持ち、家族の好み、予定をAIが把握する
  - お店：家庭の「買う予定」をもとに、作りすぎない量を仕入れられる
  - 町：余った食品を、ほしい人のところへ流す
- 個人にとっては **「あれ、家にあったっけ？」がなくなり、献立にも迷わない、便利なツール**。
- 社会にとっては、**家庭の「来週買う予定」が分かることで、お店や農家が作りすぎなくなる仕組み**。
- プライバシーの約束は **「見るだけ・教えるだけ」**：画像・映像は保存しない・送らない・公開しない。返すのは「無駄にならない・おいしい・健康に良い」アドバイスだけ（→ [privacy.md](privacy.md)）。
- 進め方の約束は **パレート改善**：参加した人は誰も損をせず、損が出そうな相手には浮いたお金の一部を回す（→ 8章）。
- まずは **スマホ版 × 1つの町の実証** から始め、ウェアラブル（カメラ付きイヤホン・ARグラス）、国、世界へと広げる。

## 2. 背景と課題

### 2-1. 日本の現状
- 日本の食品ロスは **年に約460万トン台**。お店などから出る分と家庭から出る分が **ほぼ半々** ※最新の統計値は要確認
- 2019年の食品ロス削減推進法で、**市町村は削減推進計画を作るよう努めることになった**。
- ゴミ処理は市町村の大きな支出。食品は水分が多く、燃やすのに余計な費用がかかる。

### 2-2. ロスが出る本当の理由（経済学の見方）
| 場所 | 原因 |
|---|---|
| **家庭** | 家に何があるか忘れる、期限に気づかない、買いすぎる、家族の予定が変わる |
| **お店** | 明日のお客さんの数が分からない → 売り切れの損を避けるため多めに仕入れる |
| **生産者** | 何がどれだけ売れるか分からない、形が悪いと出荷できない（規格外） |
| **全体** | 「ほしい人」と「余っている所」の情報がつながっていない／捨てる費用が安い |

> 家庭とお店の問題の根っこは同じで、**「必要な量が事前に分からない」という情報の問題**。
> たべものすべてAIは、この情報をつなぐことで解決する。

### 2-3. 気をつけたい落とし穴
余った食品を安く売るツール **だけ** を入れると、お店が「余っても売れるから」と仕入れを増やし、ロスが減らないおそれがある。
→ 本企画は **予測で余りそのものを減らすこと** を中心に置く。

## 3. システムの全体像

```
┌─────────────── 個人・家庭 ───────────────┐
│ 買う：ウェアラブルカメラ／レシート／ネット通販の履歴     │
│ しまう：冷蔵庫カメラ・重さを測るマット                 │
│ 使う：キッチンでの声と映像                            │
│ 捨てる：ゴミ箱のカメラ・はかり                         │
│ 気持ち：食べたいもの・家族の好み・予定・健康・食費      │
│   → 在庫と期限を把握 → 献立と買い物リストを作る         │
└──────────────────────────────────┘
              ↓ 個人が分からない形の「来週買う予定」
┌─────────────── 町 ───────────────┐

┌──────────── 国・世界 ────────────┐
│ 農家・メーカー：生産計画／物流：ムダな輸送を減らす       │
│ 余っている地域と足りない地域の見える化                  │
└──────────────────────────────────┘
```

## 4. 個人・家庭の機能

### 4-1. 在庫の把握：家の中を全部撮らなくても分かる
> **家の在庫 ＝ 買ったもの − 使ったもの − 捨てたもの**

| タイミング | 測り方（センシング） | 分かること |
|---|---|---|
| 買う | ウェアラブルカメラでカゴの中を認識／レシートの読み取り／ネットスーパーの履歴 | 何をいつ買ったか |
| しまう | 冷蔵庫の扉を開けたときに撮影、重さを測るマット | どこに何があるか・残りの量 |
| 使う | 「卵2個使った」の声、調理中の映像 | 何を使ったか |
| 捨てる | ゴミ箱のカメラ・はかり | 何をどれだけ捨てたか → 次の買い物を改善 |

**賞味期限**：パッケージの文字を読み取る／読めないときは食品の種類ごとの目安で推定する。

### 4-2. 気持ちと好み
| 情報 | 取り方 |
|---|---|
| 今日食べたいもの | イヤホンで「今日なに食べたい？」と聞く |
| 家族の好み | 残した量、「おいしい」のひとことから学ぶ |
| 予定 | カレンダー（外食・出張・合宿で量を調整） |
| 健康 | 塩分・アレルギー・持病 |
| 食費 | 今月の残り予算 |

### 4-3. 献立とレシピ
- **期限が近い順に使い切る献立** を数日分まとめて考える。
- 「冷蔵庫のあまりもの」だけで作れるレシピを出す。
- 家族の人数・好み・健康に合わせて量と味付けを変える。

### 4-4. スーパーでの使い方（ウェアラブル）
画面を見ずにすむよう、**基本はイヤホンの声**。ARグラスは補助として使う。

- 🎧「牛乳は家にまだ1本あります。期限はあさってです」
- 🎧「この値引きの豚肉なら、家のキャベツと合わせて回鍋肉にできます」
- 🎧「火曜は外食の予定なので、3日分で足ります」

## 5. 町の機能（自治体と組む）

### 5-1. お店の需要予測（このシステムの中心）
- 利用者の「来週買う予定」を、**個人が分からない形で町全体分まとめて**お店に伝える。
- 天気・曜日・学校行事・町のイベントと合わせて、**作る量・仕入れる量を提案** する。
- 利用者が増えるほど予測が正確になり、作りすぎが減る。

### 5-2. 値段の自動調整
- 最初は「閉店○時間前に○%引き」のルールから始める。
- 慣れてきたら、期限と残り数に合わせて自動で値下げする（電子棚札・アプリ通知）。

### 5-3. 余りを町の中で回す
**① 近所の住民**（家の在庫と照らして「これ使えます」と通知）→ **② 子ども食堂・フードバンク・福祉施設** → **③ 堆肥・家畜のエサ**

### 5-4. 自治体のダッシュボード
- 町全体で減らした量（kg）・CO₂・ゴミ処理費・参加店の利益を表示する。
- 食品ロス削減推進計画の進み具合を、数字で報告できる。

## 6. 国・世界へのつながり

| 単位 | AIが出すもの | 減るロス |
|---|---|---|
| 個人・家庭 | 使い切る献立・買い物リスト | 家庭のロス（全体の約半分） |
| 町 | お店ごとの仕入れの提案、余りのマッチング | お店の作りすぎ・売れ残り |
| 国 | 地域ごとの需要の見通しを農家・メーカー・物流に | 作りすぎ、規格外品、ムダな輸送 |
| 世界 | 余っている地域と足りない地域の見える化 | 生産・貿易のムダ、食料が足りない地域への支援 |

**全体最適の考え方**：個人が自分にとって得な選択をする（安く・おいしく・使い切る）だけで、データを通じて社会全体のロスが減る。「個人の得」と「みんなの得」が同じ方向を向くように仕組みを作る。

## 7. 行動を変える仕組み（インセンティブ設計）

| 対象 | 仕組み |
|---|---|
| 住民 | 予定を共有する・余りを買う・家庭のロスを減らすと地域ポイント。ポイントは町の中のお店で使える |
| お店 | 「ロスゼロ認定店」として町が紹介する、ゴミを減らすとゴミ処理手数料が下がる |
| 寄付 | 寄付した量を見える化して感謝を伝える、税制優遇の案内 |
| 文化 | 「売り切れ御免」を良いことにする広報（売り切れ＝ロスがない、いいお店） |

## 8. パレート改善：誰も損をしない設計

目標は「社会全体の食品ロスを減らす」こと（功利主義的な目標）。ただし、**誰かに損を押しつけて全体の得を増やす方法はとらない**。
**誰も損をせず、誰かが得をする＝パレート改善** になるように作る。詳しくは [パレート改善の設計](pareto.md)。

### 8-1. 食品ロスは「捨てられている得」
お金と手間をかけて作ったのに捨てられている分を減らせば、浮いたお金・食べもの・時間を参加者で分け合える。

### 8-2. 関係者ごとのチェック（要点）
| 関係者 | 得 | 損が出る可能性 | 損をなくす仕組み |
|---|---|---|---|
| 家庭 | 食費・手間・迷いが減る | 我慢の押しつけ、プライバシー | 提案するだけで強制しない、同意制、映像を保存しない |
| お店 | 廃棄費用が減る、利益が増える | 定価の商品が売れにくくなる | 値引きは閉店前・数量限定、売上ではなく利益で評価 |
| 農家 | 規格外品が売れる | 買いたたかれる | 需要の見通しを農家にも公開、最低価格のルール |
| メーカー | 返品・在庫廃棄が減る | 出荷量が減る | 利益で評価、データ提供で新しい収入 |
| ゴミ処理業者 | — | 処理量が減る | 堆肥化・回収ルートを新しい仕事として委託 |
| 自治体 | ゴミ処理費が減る | 運営費がかかる | 削減できた処理費の一部で運営（成果に応じて払う） |

### 8-3. 得を分け合う仕組み
- 自治体・お店・メーカーで **浮いたお金の一部を「たべものすべて基金（仮）」に出し合う**。
- そこから、住民（地域ポイント）、定価の売上が減ったお店、仕事が減った業者に回す。
- 地域ポイントは町の中だけで使えるので、浮いたお金が町の中で回る。

### 8-4. 約束とルール
> **自分で選んで参加した人は、誰も損をしない。参加していない人も、今より悪くはならない。**

- 参加は自分で選ぶ（オプトイン）。AIの提案に従わせない。
- 段階ごとに **関係者ごとの得と損を測り、損をしている関係者が1つでもあれば、次の段階に進む前に設計を直す**。

## 9. 使うテクノロジー

| 分野 | 内容 |
|---|---|
| 画像AI | 食品・パッケージ・期限の文字を認識、レシートを読む |
| 会話AI | イヤホンで質問に答える、献立の相談にのる |
| 予測 | 家庭の消費ペース、お店の需要（最初は簡単な統計から） |

| つながり | LINE（家族の共有・住民への通知）、お店のレジとの連携、自治体のダッシュボード |
| プライバシー | 処理はできるだけ端末の中で、映像は保存しない、顔は自動でぼかす |

## 10. 進め方（段階）

| 段階 | 期間 | 内容 | 規模 |
|---|---|---|---|
| **第0段階** 準備 | 1〜2か月 | 自治体・商工会と話す、今どれだけ捨てているか測る | 1地区 |
| **第1段階** スマホ版＋小さな実証 | 6か月 | レシート・冷蔵庫の写真 → 在庫と献立。お店の余りをLINEで通知、寄付のマッチング | 家庭100世帯・10〜20店舗・子ども食堂2〜3か所 |
| **第2段階** 予測の導入 | 6か月 | 「来週買う予定」をまとめてお店に提案。値下げルールの自動化 | 家庭500世帯・30〜50店舗＋農家 |
| **第3段階** ウェアラブル対応 | 1年〜 | カメラ付きイヤホン・ARグラスでスーパーモード、冷蔵庫センサー | 希望者・提携スーパー |
| **第4段階** 町全体〜国へ | 2年〜 | 地域ポイント・堆肥化とつなぐ、近くの町へ広げる、全国の需要の見通し | 複数の自治体 |

## 11. 目標とする成果（KPI）

| 指標 | 第1段階の目標（案） |
|---|---|
| 参加家庭の食品ロス | 実証前と比べて **30%減** |
| 参加店舗の廃棄量 | 実証前と比べて **20〜30%減** |
| 寄付で届けた食品 | 月○kg（スタート時の量を測ってから決める） |
| 利用者の満足 | 「献立に迷わなくなった」「買い忘れ・買いすぎが減った」の割合 |
| 自治体 | 燃えるゴミの量・処理費の変化 |
| **パレート改善** | **損をした関係者の数 ＝ 0**（家庭・お店・農家・業者ごとに確認） |

※目標の数字は、第0段階で今の量を測ってから決め直す。

## 12. お金の流れ（事業モデル）

| 収入の元 | 内容 |
|---|---|
| 個人 | 基本は無料。ウェアラブル対応・家族の健康管理などは月額のプラン |
| お店 | 需要予測・値下げの機能の月額利用料、または成果に応じた手数料 |
| 自治体 | ゴミ処理費が減った分の一部を運営費に（成果に応じて払う方式） |
| データ | 個人が分からない形にした需要の見通しを、メーカー・農家・物流会社に提供 |
| 最初の資金 | 国の補助金・交付金（食品ロス削減・地方創生関連 ※募集状況は要確認） |

**ざっくりの費用感（第1段階）**：スマホ版はWebの試作と既存のAIを使えば **数十万〜数百万円程度** ※概算、要見積もり

## 13. リスクと対策

| リスク | 対策 |
|---|---|
| 店内でのカメラで他のお客さんが映る | 顔を自動でぼかす、映像を保存しない、端末の中で処理する |
| お店が撮影を禁止している | お店と提携して公認にする（お店にもデータという得がある） |
| 家の中のプライバシー | 撮るのは冷蔵庫の中だけ、家族それぞれがオン・オフを選べる |
| 記録が面倒で続かない | 声とカメラで自動化、手で入力しなくていいようにする |
| 余り市場ができてかえってロスが増える | 予測を中心に置く。「作った量に対して捨てた割合」で評価する |
| 食中毒など衛生の問題 | 扱う食品を決める、寄付のガイドラインに沿う、保険に入る |
| 高齢者が使えない | LINE＋電話受付、町内会・民生委員と協力（「もしもしAI」とつなぐ案も） |
| 機械が高い | 最初はスマホだけで使えるようにする |

## 14. 先行例と、この企画の新しさ

- 部分ごとの先行例はある：冷蔵庫カメラ（Samsungなど）、業務用ゴミ計量（Winnowなど）、余った食品のマッチングアプリ（TABETE、Too Good To Goなど）。
- **新しい点**：
  1. 買い物（ウェアラブル）・家庭の在庫・気持ち・家族の好みを **1つのAIでまとめる**
  2. 家庭の「来週買う予定」を **お店・町の需要予測につなげる**
  3. 個人 → 町 → 国 → 世界と **同じ仕組みで広げられる**
- ※特許を考える場合は、公開する前に先行例を調べる・出願を検討する。

## 16. 健康：食品ロスと健康を同時に良くする

くわしくは [健康](health.md)。

- **使う情報**：アレルギー、持病の制限、体重・血圧（表示をカメラで読む）、歩数・睡眠、健診の結果、食べたもの。
- **基準**：日本人の食事摂取基準などの公開データ。
- **優先順位**：① 安全（アレルギー・食中毒） > ② 健康 > ③ 好み > ④ 食品ロス > ⑤ 食費。**健康を悪くしてまで食品ロスを減らさない。**
- **下からつなぐ**：「町の人に足りない栄養」を、個人が分からない形でまとめる。それをもとに地元の農家・お店が作るもの・仕入れるものを変える。厚生労働省（健康）・農林水産省（農業）・消費者庁（食品ロス）の縦割りを、住民・農家・お店が直接つながることで越える。
- **守ること**：診断しない。病歴は特に慎重に扱い、端末の外に出さない。効果をうたわない。医師・栄養士の指示を優先する。

## 17. 自律分散の運営：役所に頼らず、下からつなぐ

くわしくは [自律分散の運営](decentralized.md)。

国や役所が上から管理するのではなく、**自分で選んで参加し、助け合い、対等につながる** 仕組みにする（無政府主義＝アナキズムの「自発的な協力と相互扶助」の考え方）。

| 原則 | 内容 |
|---|---|
| データは本人のもの | 端末の中に置く。連合学習で、集めずに学ぶ |
| 参加は自由 | 強制しない。いつでもやめてデータを消せる（パレート改善の約束と同じ） |
| 相互扶助 | 余りは近所で分け合う、共同購入、子ども食堂へ |
| 協同組合で運営 | 住民・お店・農家が持ち主。1人1票でルールと基金の分け方を決める |
| 町と町は対等に連合 | 中央のサーバーなし。町どうしが横につながり、国・世界へ広がる |

- **お金**：協同組合の会費、お店・農家の利用料、たべものすべて基金、寄付。行政の予算には頼らない。
- **行政との関係**：「頼る相手」ではなく「参加者の一人」。ゴミの収集・処理など市町村の仕事とは協力する。
- **守ること**：自律分散でも、食品衛生・個人情報・医療に関わる法律は守る。
